# ADR-057 — C-12 statique, observation des fils hors périmètre, R-390 au pire cas

- **Date** : 2026-10-18
- **Statut** : acceptée
- **Composants** : C-12 (Thread Analyzer) ; C-08, C-11 ; C-04, C-05 (observation absente)
- **Exigences** : PARTIE 5.12, R-390, R-391, T-210 à T-212 ; DM-02, DM-09 ; R-206,
  P-02 ; ADR-054, ADR-055, ADR-056
- **Demande** : Killian, 2026-10-18, « ok go c12 »

## Contexte

C-12 dit si une unité doit rester sur le fil autoritatif. La fiche combine une
**observation** (sur quels rôles de fil l'unité a-t-elle été vue ?) et une analyse
**statique** (API confinée, `ThreadLocal`, `synchronized`, champs mutables partagés,
confinement dérivé des classes).

L'observation suppose que les sondes capturent un rôle de fil (DM-02, `thread_role`,
R-204). Ce n'est pas le cas : chaque fil a son tampon de sondes et le natif voit un
identifiant de fil par tampon, mais il ne sait pas lequel est le fil autoritatif. Le lui
apprendre demande une entrée FFI ou un format d'enregistrement nouveaux : un changement
d'interface publiée, hors du périmètre de décision de l'agent.

## Décision

1. **C-12 est statique.** Sur les méthodes analysées du graphe d'appel :
   - `uses_synchronized` : une méthode `ACC_SYNCHRONIZED`, ou un `monitorenter` ;
   - `uses_locks` : un appel vers `java/util/concurrent/locks/*`, `Semaphore.acquire*`
     ou `Object.wait` ;
   - `uses_thread_locals` : un accès au domaine `ThreadLocals` (C-11), ou un appel vers
     une classe dont la chaîne de super-classes passe par `java/lang/ThreadLocal` ;
   - `reentrant` : `YES` si la racine est dans un cycle d'appels, `NO` si le graphe est
     complet sans cycle, `UNKNOWN` sinon.
2. **Confinement dérivé** (étape 3) : une classe est non sûre entre fils si elle, ou une
   de ses super-classes, déclare un champ ni `final` ni `volatile` qui est soit non
   privé (n'importe qui peut l'écrire), soit écrit par une de ses méthodes autre que le
   constructeur (ou `<clinit>` pour un statique) qui n'est pas `synchronized`. Seule une
   méthode `ACC_SYNCHRONIZED` exempte ses écritures : un bloc `synchronized { }` ne protège
   pas une écriture faite hors de lui, et les limites des blocs ne sont pas suivies. Une
   classe d'un nid (`NestHost`, `NestMembers`) voit ses champs privés mutables comptés
   comme écrits : des classes imbriquées peuvent les écrire directement (Java 11+).
   Une classe dont le bytecode ou une super-classe manque est tenue pour non sûre. La
   restriction « atteignable depuis l'état autoritatif » est remplacée par « objet non
   local » : plus large, donc plus prudente.
3. **`touches_non_threadsafe_api`** : un accès à un champ d'une classe non sûre, sur un
   objet qui n'est pas une allocation locale non échappée, ou à un statique mutable ; ou
   un graphe dont une partie reste inconnue (site non résolu, non exploré, cible sans
   code, troncature) — ce qu'on n'a pas vu peut y toucher.
4. **`main_thread_required`** (DM-09) : `YES` si l'unité touche une classe non sûre ou
   écrit un domaine de l'état du jeu (monde, chunks, entités, block entities, globaux du
   niveau, registres, capabilities) ; `NO` seulement si elle est pure — lecture seule
   connue, sans effet de bord, déterministe (C-13) — et ne touche aucune classe non sûre ;
   `UNKNOWN` sinon, traité comme `YES` (P-02). Tant que C-13 manque, `NO` n'est jamais
   atteint.
5. **Observation hors périmètre, R-390 au pire cas.** DM-09 reçoit le champ que le
   cahier prévoit, sous forme d'ensemble de rôles (`observed_roles`), `None` tant
   qu'aucune observation n'existe. La classification marque `UNSAFE` toute unité qui
   écrit (ou dont les écritures sont inconnues) quand ses rôles observés sont inconnus
   ou multiples : sans observation, on ne peut pas exclure l'exécution sur plusieurs
   fils (R-390, `UNKNOWN = CONSERVATIVE`).
6. **R-391 dans la classification** : `THREAD_SAFE` exige désormais `PURE` — aucune
   preuve d'isolation n'existe encore.

## Conséquences

- Les descripteurs portent des `ThreadFacts` ; C-13 manquant, aucun n'atteint
  `main_thread_required = NO` ni `THREAD_SAFE`.
- La plupart des unités qui écrivent deviennent `UNSAFE` : c'est le prix de l'absence
  d'observation. Lever cette prudence demande que les sondes portent le rôle de fil
  (DM-02) — décision d'interface à prendre avec Killian.
- T-210 et T-211 sont couverts ; T-212 l'est par la classification (rôles multiples, et
  rôles inconnus traités comme multiples), pas par une observation réelle.
- Métriques `rfx.thread.main_required_ratio`, `rfx.thread.unknown_ratio`.
