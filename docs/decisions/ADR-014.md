# ADR-014 : numérotation des ADR de l'agent à partir de 013

Statut : accepté

## Contexte

Le cahier des charges V1.0 (PARTIE 27.3) réserve nominativement les identifiants
`ADR-001` à `ADR-012` pour douze décisions d'architecture obligatoires, dont le contenu
est déjà arrêté par le document (ADR-001 Forge comme plateforme initiale, ADR-004 JNI +
DirectByteBuffer, ADR-009 Cranelift comme backend optionnel, etc.). L'annexe A.3
confirme le périmètre : « Décisions : ADR-001..ADR-012 ».

Toute décision prise par l'agent d'implémentation et non prévue par le CDC doit donc
recevoir un identifiant qui n'entre pas en collision avec cette plage.

## Options envisagées

**A. Numéroter les ADR de l'agent à partir de 013**

- (+) aucune collision possible : la plage 001-012 reste exactement celle du CDC ;
- (−) la numérotation ne suit pas l'ordre chronologique de rédaction.

**B. Réutiliser les numéros libres dans 001-012**

- (−) collision garantie dès que les ADR obligatoires seront rédigés.

**C. Préfixer les ADR de l'agent (`ADR-A-001`)**

- (−) diverge du format imposé par la PARTIE 27.3.

## Décision

Option A. Les identifiants `ADR-001` à `ADR-012` sont réservés aux douze ADR
obligatoires listés en PARTIE 27.3 et seront rédigés au jalon où leur décision devient
effective. Tout ADR issu d'une décision de l'agent d'implémentation prend le prochain
numéro libre à partir de `ADR-013`.

## Conséquences

Positives :

- la traçabilité CDC vers ADR reste bijective sur la plage 001-012 ;
- aucun renumérotage rétroactif ne sera nécessaire.

Négatives :

- les fichiers `ADR-001.md` à `ADR-012.md` seront absents du dépôt jusqu'à la rédaction
  de la décision correspondante. L'état de cette liste est suivi dans `tasks/todo.md`.
