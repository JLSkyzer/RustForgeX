# ADR-040 — Échantillonner pendant le tick seulement

- **Date** : 2026-10-16
- **Statut** : accepté (décision de Killian, correctif A)
- **Composant** : C-05 (profileur)
- **Exigences** : T-140, R-322, ADR-037, ADR-039

## Contexte

ADR-039 a laissé le classement presque vide sous `medium` sur le modpack réel (2 à 5
unités). Le recensement des trames inconnues des trois exécutions `t140-h` en donne la
cause : **99,3 % des prélèvements ne tombent sur aucune méthode sondée**.

- 61 % sont pris dans `MinecraftServer#m_5667_` : entre deux ticks, le fil autoritatif
  attend le suivant. Un tick dure 11,5 ms sur 50.
- 32 % sont pris dans `IntLatch#waitUntil` d'un mod du modpack qui tique les dimensions
  sur ses propres fils : le fil autoritatif les attend. Ce cas relève d'ADR-041.

## Décision

L'échantillonneur ne prélève que pendant la **phase de jeu** du tick : entre la fin du
hook `PRE` et le début du hook `POST`. Le drain et le vidage, qui sont le travail de
RUSTFORGE-X, en sont exclus. Un prélèvement évité est compté (`samples_outside_tick`
dans le fichier du banc).

La densité de prélèvement pendant le tick n'est pas censée changer : la cadence reste
réglée sur le coût mesuré (ADR-037), et seuls les prélèvements hors tick disparaissent.

## Vérification

`medium` sur le modpack réel, trois exécutions (`t140-i/tick-only`), comparées aux trois
de `t140-h` (ADR-039) :

| | `t140-h` | **`t140-i`** |
|---|---|---|
| MSPT p50 | 11,4 / 11,9 / 11,9 ms | 14,7 / 16,5 / 11,8 ms |
| piles prélevées | 38 269 / 34 710 / 37 750 | 8 659 / 9 212 / 11 156 |
| dont dans `m_5667_` | 23 636 / 21 174 / 23 261 | 0 |
| prélèvements évités hors tick | — | 12 613 / 9 810 / 19 443 |
| dans `IntLatch#waitUntil` | 12 300 / 11 449 / 12 236 | 8 473 / 8 998 / 10 885 |
| attribués à une sonde | non relevé | 9 / 15 / 9 |
| unités classées | 3 / 2 / 5 | 0 / 1 / 0 |
| coût relevé par tick | 0,14 / 0,40 / 0,27 ms | 0,49 / 1,30 / 0,87 ms |
| niveau final | `DEEP`, `THROTTLED`, `LIGHT` | `THROTTLED` ×3 |

Ce que cela établit :

- **le mécanisme fonctionne** : plus aucune pile n'est prise dans l'attente du tick
  suivant ;
- **il ne suffit pas** : pendant le tick, 97 à 98 % des piles du fil autoritatif sont
  l'attente des fils de dimension. Le classement reste vide. C'est ADR-041 ;
- **le coût relevé est plus élevé et le gouverneur bride trois fois sur trois.** La
  cause n'est **pas établie**. L'échantillonnage ne l'explique pas à lui seul : il a
  pris moins de piles pendant le tick qu'avant (8 700 à 11 200, contre 11 000 à 14 600
  hors `m_5667_`). Le MSPT est aussi plus élevé dans deux exécutions sur trois, et la
  mesure de ligne de base reste bruitée sous ce profil (ADR-038). Aucune attribution
  n'est retenue sans exécution de contrôle.

## Conséquences

- Correctif conservé : il retire des prélèvements qui ne disaient rien du tick.
- La question du classement vide passe à ADR-041 (les fils de travail).
- La hausse du coût relevé est une question ouverte. Si elle persiste après ADR-041,
  une exécution de contrôle sans échantillonnage
  (`-Drustforgex.instrumentation.stack_sampling=false`) la départagera.
