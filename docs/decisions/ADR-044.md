# ADR-044 — Planificateur : `crossbeam-deque` pour les files à vol de travail

- **Date** : 2026-10-16
- **Statut** : accepté
- **Composants** : C-17 (Scheduler), C-18 (Worker Runtime), crate `rfx-scheduler`
- **Exigences** : PARTIE 5.17.1, 5.17.3, 5.17.8, PARTIE 19.1, `CLAUDE.md` §4.2 et §9

## Contexte

La PARTIE 5.17 impose des files à vol de travail de Chase-Lev (LIFO pour le propriétaire,
FIFO pour le voleur) et une file d'injection sans verrou. Une telle file s'écrit avec des
lectures et écritures atomiques sur une mémoire partagée qu'aucun propriétaire unique ne
tient : en Rust, c'est du code `unsafe`. Or ce dépôt n'autorise `unsafe` que dans
`rfx-ffi` et dans la sonde matérielle (`CLAUDE.md` §4.2). Une file maison exigerait aussi
loom et Miri pour être crue, ce que la PARTIE 19.1 demande justement pour ces structures.

## Décision

`rfx-scheduler` utilise **`crossbeam-deque` 0.8** (`Worker`, `Stealer`, `Injector`). C'est
l'implémentation de référence de Chase-Lev en Rust, celle sur laquelle repose `rayon`,
maintenue par le projet crossbeam, sous licence **MIT ou Apache-2.0**. Elle entraîne
`crossbeam-epoch` et `crossbeam-utils`, mêmes auteurs, même licence.

Le crate `rfx-scheduler` lui-même reste sans `unsafe` (`forbid`).

## Conséquences

- `SECURITY.md` liste la dépendance dans son SBOM. `NOTICE` la listera quand
  `rfx-ffi` liera le planificateur : la bibliothèque native ne l'embarque pas encore.
- La file d'endormissement des fils de travail inactifs utilise un `Mutex` et une
  `Condvar` de la bibliothèque standard. Ce verrou n'est pris que pour s'endormir, et par
  le soumetteur seulement s'il existe un fil endormi : il n'est pas dans le chemin
  d'exécution d'une tâche, ce que la PARTIE 5.17.8 vise.
