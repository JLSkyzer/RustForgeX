# ADR-013 : layout du dépôt — sources Java à la racine plutôt que sous `java/`

Statut : accepté

## Contexte

Le cahier des charges V1.0 se contredit sur l'emplacement des sources Java :

- la PARTIE 3.6 (« Arborescence du dépôt ») place le code Java dans
  `java/src/main/java/dev/rustforgex/` ;
- la PARTIE 23.2 (« Organisation du build ») spécifie que les artefacts natifs sont
  copiés dans `src/main/resources/natives/<os>-<arch>/`, chemin qui n'existe que si le
  sourceSet principal est à la racine du dépôt.

Ces deux sections ne peuvent pas être vraies simultanément avec un build Gradle
mono-projet. Le MDK Forge 1.20.1 génère par ailleurs le layout racine par défaut.

## Options envisagées

**A. Sources à la racine (`src/main/java/`)**

- (+) layout par défaut de ForgeGradle 6 : aucune configuration de sourceSet, run
  configurations IntelliJ générées valides sans retouche ;
- (+) cohérent avec la PARTIE 23.2 et avec l'extrait normatif de `build.gradle` ;
- (+) `processResources`, `reobfJar` et la tâche `copyNative` fonctionnent tels que
  spécifiés, sans réécriture de chemins ;
- (−) diverge littéralement de l'arborescence de la PARTIE 3.6.

**B. Sources sous `java/` (PARTIE 3.6 stricte)**

- (+) conforme à la lettre de la PARTIE 3.6 ;
- (−) impose de reconfigurer les sourceSets, les chemins de `processResources`, la
  tâche `copyNative` de la PARTIE 23.2 et les run configurations IntelliJ ;
- (−) introduit une divergence avec l'extrait normatif de `build.gradle` (23.2) : elle
  ne supprime donc pas la contradiction, elle la déplace.

## Décision

Option A. Les sources Java restent à la racine, dans `src/main/java/dev/rustforgex/`.
Le workspace Rust vivra dans `crates/` à côté, comme prévu par la PARTIE 3.6.

Le découpage en sous-paquets de la PARTIE 3.6 (`bootstrap/`, `forge/`, `instrument/`,
`bridge/`, `snapshot/`, `commit/`, `config/`, `command/`, `ui/`, `diag/`) est conservé
intégralement sous `src/main/java/dev/rustforgex/`.

Application du contrat agent 1.2 : le document étant ambigu, l'option la plus
conservatrice pour la correction est retenue — celle qui n'oblige à réécrire aucun
chemin déjà normatif par ailleurs.

## Conséquences

Positives :

- aucun écart avec l'extrait normatif de `build.gradle` (PARTIE 23.2) ;
- les tâches `buildNative` / `copyNative` / `hashNative` s'écriront telles quelles ;
- outillage Forge standard, donc moins de surface de panne au build.

Négatives :

- l'arborescence de la PARTIE 3.6 doit être lue en substituant `java/src/` par `src/`.
  Cette substitution est rappelée dans `docs/AGENT.md`.
